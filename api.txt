API-Uebersicht

Basis
- Backend: http://localhost:3001
- API-Basis lokal via Vite-Proxy: /api

Format
- JSON fuer Request und Response
- Fehlerantworten enthalten in der Regel:
  - fehler

1. GET /api/gesundheit
Zweck:
- einfacher Health-Check des Backends und der Datenbankverbindung

Response Beispiel:
{
  "ok": true,
  "server_zeit": "2026-04-08T22:00:00.000Z"
}

4c. POST /api/ausleiher/synchronisieren
Zweck:
- synchronisiert `ausleiher` aus den Fachtabellen `schueler`, `lehrkraefte` und `klassen`

Verhalten:
- legt fehlende Ausleiher an
- aktualisiert Namen, Barcodes und Zuordnungsfelder
- setzt veraltete synchronisierte Ausleiher auf inaktiv

Erfolgsantwort:
{
  "meldung": "Ausleiher wurden mit den Fachtabellen synchronisiert.",
  "statistik": {
    "schueler": 200,
    "lehrkraefte": 8,
    "klassen": 86
  }
}

5. POST /api/ausleihen
Zweck:
- erstellt eine neue Ausleihe fuer ein Exemplar

Request Body:
{
  "exemplar_id": 1,
  "ausleiher_id": 1,
  "faellig_am": "2026-04-20T12:00",
  "kommentar_ausgabe": "Fuer Projektwoche"
}

Pflichtfelder:
- exemplar_id
- ausleiher_id

Verhalten:
- prueft, ob Exemplar existiert
- prueft, ob Exemplar verfuegbar ist
- schreibt Ausleihe
- setzt Exemplarstatus auf ausgeliehen
- schreibt Historieneintraege

Erfolgsantwort:
{
  "id": 9,
  "meldung": "Ausleihe erfasst."
}

Moegliche Fehler:
- 400 wenn exemplar_id oder ausleiher_id fehlt
- 404 wenn Exemplar nicht gefunden
- 409 wenn Exemplar nicht verfuegbar

6. POST /api/ausleihen/:id/rueckgabe
Zweck:
- verbucht eine Rueckgabe zu einer offenen Ausleihe

Request Body:
{
  "zustand_bei_rueckgabe": "gut",
  "kommentar_rueckgabe": "Vollstaendig zurueck"
}

Pflichtfelder:
- zustand_bei_rueckgabe

Verhalten:
- setzt rueckgabe_am
- setzt zustand_bei_rueckgabe_id
- setzt Ausleihstatus auf zurueckgegeben
- setzt Exemplarstatus auf verfuegbar oder defekt
- setzt Exemplarzustand
- schreibt Historieneintraege

Regel:
- wenn zustand_bei_rueckgabe = beschaedigt
  dann Exemplarstatus = defekt
- sonst Exemplarstatus = verfuegbar

Erfolgsantwort:
{
  "meldung": "Rueckgabe verbucht."
}

Moegliche Fehler:
- 400 bei fehlendem Rueckgabezustand
- 404 wenn Ausleihe oder Rueckgabezustand nicht gefunden
- 409 wenn Ausleihe bereits abgeschlossen

9. PATCH /api/exemplare/:id
Zweck:
- aktualisiert Exemplar-Felder direkt auf Objektebene

Request Body:
{
  "status": "in_reparatur",
  "zustand": "beschaedigt",
  "standort_id": 3,
  "notizen": "Displaybruch links unten",
  "ausgeloest_von": "weboberflaeche"
}

Felder:
- status optional
- zustand optional
- standort_id optional
- notizen optional
- ausgeloest_von optional

Verhalten:
- aktualisiert das Exemplar
- schreibt Historieneintraege bei echten Aenderungen:
  - status_aenderung
  - zustandsaenderung
  - standortaenderung
  - notiz_aenderung

Erfolgsantwort:
{
  "meldung": "Exemplar aktualisiert."
}

Moegliche Fehler:
- 400 bei ungueltiger Exemplar-ID
- 404 wenn Exemplar nicht gefunden

Aktuelle serverseitige Fälligkeitslogik
- Quelle: ausleihen.faellig_am
- Ergebnis wird im Feld offene_ausleihen[].faelligkeit geliefert

Statuswerte:
- ueberfaellig
- bald_faellig
- ohne_frist
- unkritisch

Zuordnung:
- faellig_am = NULL -> ohne_frist
- Datum in Vergangenheit -> ueberfaellig
- innerhalb naechster 2 Tage -> bald_faellig
- sonst -> unkritisch

Wichtige Hinweise fuer spaeter
- Standardfristen aktuell noch nicht automatisch im Backend gesetzt
- Authentifizierung/Rollen sind noch nicht eingebaut
- Historie ist bereits objekt- und ausleihbezogen, aber noch ohne Schadensmodul
